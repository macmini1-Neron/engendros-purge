## Locked design decisions (from the design discussion)
1. **Mini-physics, no external engine.** Reuse the lab's deterministic fixed-substep `FallingBody` (hinge trunks rest on obstacles; tumble debris). Seeded → co-op replay.
2. **Buildings: windows + wall breaches, NO collapses.** Per-pane glass; ~1.5–2 m breach segments removed by HE; lazy-split merged rendering (intact = 1 merged mesh, rebuild-minus-dead on damage). Data model future-proofs collapse later.
3. **Caliber model = hardness tiers 0–5 × penetration class** + special ammo behaviors:
   - **APFSDS (refined per owner):** NO explosion. Along the ray it **OBLITERATES fragile/light parts (material tier ≤ 2: glass/wood/sheetmetal/trunk/grass/props) = killed + debris**, and through **structural masonry/armor (tier ≥ 3: brick/concrete/steel)** it makes a **through-hole only (part stays, dead:false)**. A **spall cone** behind each penetrated structural wall does **real damage** (kills fragile props + hurts enemies/players in the cone). "It destroys things, just not by exploding."
   - **HE (bazooka, later 115mm):** blast removes wall segments tier ≤ blastTier within r1; shatters all glass within wider r2; shrapnel damages enemies/players.
   - Bullets: `pen < tier` ⇒ cosmetic decal/chip; `pen ≥ tier` ⇒ HP damage. Shotgun pellet pen 1 (breaks fences). Tank shells get gravity.
4. **Fire = Far-Cry-2 hybrid, phased ember-chain first.** See Phase 8.
5. **Terrain = heightmap + height-sampling collision (Approach A), T2 walkable.** Keep AABB world + SpatialGrid + buildgen for man-made objects; only the GROUND becomes a heightfield.

## Key contracts (get these right — everything depends on them)
- **`MATERIALS` registry** (in `src/destruct.js`), each: `{ tier, hp, debris, sound, fuel }`. `fuel = 0` ⇒ never ignites (glass/sheetmetal/brick/concrete/steel). `fuel > 0` ⇒ burn-time + ignites neighbors (wood 6, trunk 10, grass 2). Fire READS this registry — single source of truth. Add `sound` keys (glass/wood/metal/masonry) for later audio.
- **Destructible part metadata** on collision boxes: `{ min, max, dmat, dhp, dpart, downer }` generalizing the existing `struct/_ref` fortification pattern (`world.js` attackStructure/destroyStructure + grid add/removeBox). `downer` back-ref solves "world.boxes has no mesh back-reference."
- **Terrain contract:** `World.terrainHeightAt(x,z) → y` MUST be **deterministic, C0-continuous, seeded, pure** (no per-call RNG) — co-op clients reconstruct enemy Y locally (esnap carries only x,z — `mp.js:708`), so host & client must agree bit-for-similar. Also `terrainNormalAt`, `terrainSlopeAt`, `isPlaceable(x,z,r,kind)`. On flat maps these return y=0 / true (byte-identical to today).
- **Fixed-step clock:** physics + fire run on an internal accumulator (`src/simclock.js`, 1/120 physics, ~1/10 fire), NEVER raw variable dt. The game loop stays variable-dt; only these subsystems sub-step. Pattern proven in `feat/destructlab:tools/destructlab/fallphys.js`.
- **Co-op authority:** all new authoritative logic behind `hostSim = !mp.active || mp.isHost`. Destruction/fire = host-authoritative, **event + seed** synced (broadcast "wall X destroyed (seed S)" / "fire ignited at C (seed S)"; clients reproduce cosmetic fragments/flames locally). NEVER stream per-fragment transforms. Terrain is static deterministic data → no sync needed beyond the seed.
- **Perf gates (per destruction spec §7, measured in the demo):** ≥ 60 fps with forest + a burning tree + a building breach event; debris pooled (instanced, ≤ ~1 extra draw call); building rebuild ≤ 4 ms/event; ≤ 8 concurrent FallingBodies; fire capped (active cells + object fires). Report real numbers.
